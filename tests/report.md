# Оценка способности LLM предсказывать психометрические показатели MCQ вопросов

**Курс:** Основы программирования (C#, бакалавриат, 1-й курс)  
**Модель:** gemini-3-flash-preview (через LiteLLM прокси litellm.labs.jb.gg)  
**Дата:** 2026-04-29

---

## Аннотация

Исследование проверяет, может ли языковая модель (LLM) предсказать, насколько трудным окажется вопрос для студентов и насколько хорошо он отделяет сильных от слабых, — используя только текст вопроса без знания правильных ответов. Реальные показатели получены по ответам 1 957 студентов. Из 99 вопросов курса 52 исключены как тривиальные; анализ проведён на 47 оставшихся: 32 с несколькими правильными вариантами (multiple-select) и 15 с одним (single-select).

**Главный результат:** Для вопросов с несколькими правильными вариантами модель хорошо ранжирует вопросы по сложности (корреляция r = 0.72), но систематически считает их труднее, чем они есть на самом деле — в среднем ошибается на 40 процентных пунктов. Для вопросов с одним правильным ответом надёжная корреляция не обнаружена. Показатель различения (насколько вопрос разделяет сильных и слабых студентов) модель не предсказывает ни для одного типа вопросов.

---

## 1. Введение

Хороший тестовый вопрос должен обладать двумя свойствами: он не должен быть тривиальным (т.е. правильно отвечать должны не все подряд) и должен различать сильных студентов от слабых. Обычно это проверяется по статистике реальных ответов — после того как курс уже прошли сотни человек. Если же LLM могла бы предсказывать эти свойства заранее по тексту вопроса, разработчики курсов могли бы улучшать материалы до их выхода в использование.

**Исследовательский вопрос:** Можно ли использовать LLM для предсказания (а) сложности MCQ вопроса и (б) его способности разделять сильных и слабых студентов, если модель не знает, какие ответы правильные?

---

## 2. Данные

### 2.1 Вопросы

Из курса «Основы программирования» (платформа ulearn.me, C#, 1-й курс бакалавриата) извлечено **99 MCQ вопросов** из 13 лекционных модулей. Отфильтрованы вопросы, зависящие от изображений, и нетекстовые типы. Вопросы охватывают темы: базовый синтаксис, типы, ветвления, массивы, коллекции, тестирование, алгоритмическая сложность, рекурсия, сортировка, ООП, наследование.

**Фильтрация тривиальных вопросов:** Исключены 52 вопроса, на которые студенты отвечали правильно в более чем 90% случаев. Такие вопросы слишком просты для анализа — вариация в ответах слишком мала. Оставшиеся **47 вопросов** имеют долю правильных ответов от 46% до 90%, среднее — 77%.

Из 47 вопросов **32 — типа «несколько правильных» (multiple-select)**, 15 — типа «один правильный» (single-select).

### 2.2 Ответы студентов

Данные получены через API ulearn.me. Скачаны ответы из **108 активных групп** (≥ 5 студентов). После анонимизации (SHA-256) и дедупликации датасет содержит **122 384 ответа** от **1 963 уникальных студентов**. Для вычисления показателей оставлены студенты с ≥ 5 попытками — **1 957 студентов**.

API возвращает только итоговый балл (0 — неверно, 1 — верно). Конкретные выборы вариантов ответа недоступны.

### 2.3 Контекст прохождения

Вопросы встроены в учебные материалы в режиме «читаешь лекцию — сразу отвечаешь». Это формативный (самопроверочный) формат, а не экзамен — отсюда высокий общий уровень правильных ответов (77% в среднем по нетривиальным вопросам).

## 3. Методы

### 3.1 Психометрические показатели

**Индекс сложности** — доля студентов, ответивших правильно. Обозначается _p_. Чем выше — тем легче вопрос: p = 0.9 означает «90% студентов ответили верно», p = 0.5 — «угадывали чаще всего».

**D-индекс (показатель различения)** — разность между долей правильных ответов у «сильных» и «слабых» студентов:

$$D = p_\text{топ 30\%} - p_\text{низ 30\%}$$

Сильные студенты — те 30%, у кого самый высокий средний балл по курсу (в нашей выборке: 97% правильных ответов в среднем). Слабые — те 30% с наименьшим средним баллом (71% в среднем). D = 0.40 означает: сильные отвечают правильно на 40 п.п. чаще, чем слабые. D ≥ 0.30 считается приемлемым, D ≥ 0.40 — хорошим.

### 3.2 Методология предсказания

Модели предъявлялся вопрос с вариантами ответов **без пометок о правильности** (без ✓/✗). В системном промпте указывался контекст: это формативные квизы, студенты — первокурсники, вопрос читается сразу после объяснения темы. Код, если он предшествовал вопросу в квизе, включался в запрос.

Модель просили предсказать вероятность выбора каждого варианта отдельно для сильных (top 30%) и слабых (bottom 30%) студентов. Из этих вероятностей вычислялись итоговые показатели:

**Для вопросов с одним правильным ответом** (single-select): предсказанная сложность = вероятность выбора правильного варианта.

**Для вопросов с несколькими правильными ответами** (multiple-select): вопрос считается решённым только если студент выбрал все правильные варианты и не выбрал ни одного неправильного. Поэтому предсказанная сложность вычисляется как произведение:

$$\hat{p} = \prod_{i \in \text{верные}} p_i \;\times\; \prod_{j \in \text{неверные}} (1 - p_j)$$

Например, если вопрос имеет 2 правильных варианта с вероятностями 0.90 и 0.80, и один неправильный с вероятностью 0.20, то $\hat{p} = 0.90 \times 0.80 \times (1 - 0.20) = 0.576$.

Параметры запуска: temperature = 0.2, max_tokens = 4096. Каждый вопрос обрабатывался независимо.

### 3.3 Оценка качества предсказаний

Используются следующие метрики:

- **MAE** (средняя абсолютная ошибка) — на сколько процентных пунктов в среднем ошибается модель. MAE = 0.10 означает ошибку ±10 п.п.
- **Корреляция Пирсона (r)** — насколько хорошо ранжирование вопросов по сложности у модели совпадает с реальным. Шкала от −1 до +1: r = 1 — идеальное совпадение, r = 0 — модель бесполезна (результат как случайный), r = −1 — модель инвертирует ранжирование.
- **Систематическая ошибка (bias)** — среднее отклонение предсказаний от реальности. Отрицательное значение означает, что модель систематически занижает.

## 4. Результаты

### 4.1 Вопросы с несколькими правильными ответами (multiple-select, n = 32)

Это основной по числу тип вопросов в датасете. Реальный уровень правильных ответов: от 46% до 90%, среднее — 75.5%.

| Метрика | Значение |
|---------|---------|
| MAE | **0.403** (ошибка ±40 п.п. в среднем) |
| Корреляция r | **+0.724** |
| Систематическая ошибка | **−0.403** (модель занижает) |
| Среднее предсказанное p | 0.352 |
| Среднее реальное p | 0.755 |

**Ранжирование** работает хорошо (r = 0.72): модель в целом верно определяет, какие вопросы труднее каких — хотя абсолютные числа сильно занижены. Вопрос, который студенты решают в 85% случаев, модель оценивает примерно как 45%.

**Причина занижения:** Произведение множества вероятностей даёт маленькое число уже при умеренных неопределённостях. Вопрос с 4 правильными вариантами по 0.95 каждый даёт $0.95^4 \approx 0.81$ — ещё разумно. Но если добавить 2 неправильных по 0.30, получаем $0.81 \times 0.70^2 \approx 0.40$. Модель недооценивает, как консистентно студенты применяют только что полученные знания.

| D-метрика | Значение |
|---------|---------|
| MAE | **0.398** |
| Корреляция r | **−0.395** |
| Систематическая ошибка | **+0.323** (модель завышает D) |

D-индекс модель предсказывает плохо: корреляция отрицательная, а систематическая ошибка — завышение на 0.32. Среднее предсказанное D = 0.53, реальное среднее = 0.20.

**Примеры предсказаний для multiple-select:**

| Вопрос | Реальный p | Предск. p | Реальный D | Предск. D |
|--------|-----------|-----------|-----------|-----------|
| L080 Estimation q0 (5 правильных из 6) | 0.461 | 0.006 | — | 0.010 |
| L070 UnitTests q3 (3 из 4) | 0.546 | 0.122 | 0.284 | 0.152 |
| L030 Ifs q3 (6 из 6) | 0.582 | 0.363 | 0.205 | 0.570 |
| L150 Structures q3 (2 из 3) | 0.888 | 0.659 | 0.237 | 0.524 |

### 4.2 Вопросы с одним правильным ответом (single-select, n = 15)

Реальный уровень правильных ответов: от 49% до 90%, среднее — 80%.

| Метрика | Значение |
|---------|---------|
| MAE | **0.340** (ошибка ±34 п.п. в среднем) |
| Корреляция r | **−0.158** |
| Систематическая ошибка | **−0.292** (модель занижает) |

Корреляция практически отсутствует (r = −0.16): ранжирование вопросов по сложности не совпадает с реальным. Модель занижает p — студенты решают в 80% случаев, а модель предсказывает в среднем 51%.

| D-метрика | Значение |
|---------|---------|
| MAE | **0.382** |
| Корреляция r | **−0.399** |
| Систематическая ошибка | **+0.149** |

D-индекс также не предсказывается.

**Примеры предсказаний для single-select:**

| Вопрос | Реальный p | Предск. p | Ошибка |
|--------|-----------|-----------|--------|
| L080 Complexity q3 | 0.871 | 0.165 | −0.706 |
| L080 Complexity vs Speed q1 | 0.816 | 0.150 | −0.666 |
| L080 Complexity q1 | 0.890 | 0.500 | −0.390 |
| L020 Style2 q3 | 0.485 | 0.765 | +0.280 |
| L060 StringQuiz q0 | 0.875 | 0.375 | −0.500 |

Хуже всего — вопросы по O-нотации и алгоритмической сложности: правильные термины знакомы студентам из лекции, но модель оценивает их как терминологически трудные.

## 5. Обсуждение

### 5.1 Почему multiple-select ранжируется лучше single-select?

Неожиданный результат: ранжирование по сложности для вопросов с несколькими правильными ответами (r = 0.72) получилось лучше, чем для вопросов с одним (r = −0.16). Вероятное объяснение:

- **Структурная информация.** Число правильных вариантов и «уверенность» модели в каждом из них дают больше сигналов о сложности. Вопрос с 5 правильными вариантами из 6, где один нестандартный — объективно сложнее, чем вопрос с 2 правильными из 3.
- **Малая выборка.** 15 вопросов — слишком мало, чтобы надёжно оценить корреляцию. Одна-две ошибки на выбросах переворачивают картину.

### 5.2 Почему модель систематически занижает сложность?

Для обоих типов вопросов модель думает, что студентам труднее, чем есть на самом деле. Причина — **контекст изучения**. Студент читает объяснение и сразу отвечает на вопрос по только что прочитанному. В этом режиме 77–90% правильных ответов — норма. Модель же оценивает «объективную» трудность терминов и концепций без учёта того, что студент только что прочитал нужный абзац.

### 5.3 Почему D-индекс не предсказывается?

Показатель различения зависит не от сложности формулировки, а от того, попадает ли вопрос в «зону различения» конкретной аудитории. Если сильные студенты отвечают в 95% случаев, а слабые — в 85%, то D = 0.10 — и это не потому что вопрос плохой, а потому что аудитория однородная. Модель видит только текст вопроса — она не знает, насколько однородна конкретная студенческая аудитория. Поэтому r(D) ≈ 0 — ожидаемый результат.

### 5.4 Ограничения

1. **Малая выборка single-select (n = 15).** Корреляция на 15 вопросах статистически не значима — возможны случайные флуктуации.

2. **Один курс, один формат.** Результаты относятся к формативным квизам CS-курса первого курса. Для суммативных экзаменов или других дисциплин картина может отличаться.

3. **Нет данных о конкретных выборах студентов.** API возвращает только 0/1, поэтому нельзя проверить, правильно ли модель предсказывает, какие именно дистракторы привлекают студентов.

4. **Промпт не оптимизировался.** Один вариант промпта для всех вопросов. Явное указание типа вопроса (single vs multiple) и «формативный формат после лекции» могут улучшить результат.

## 6. Заключение

После исправления формулы расчёта для multiple-select вопросов исследование выявило следующее:

- **Ранжирование вопросов по сложности (multiple-select):** LLM способна определять, какие вопросы относительно труднее — корреляция r = 0.72. Однако абсолютные значения систематически занижены примерно на 40 п.п.: вопросы, которые студенты решают в 75% случаев, модель оценивает примерно в 35%.

- **Ранжирование вопросов по сложности (single-select):** На выборке из 15 вопросов надёжной корреляции не обнаружено.

- **D-индекс (различение сильных и слабых):** Не предсказывается ни для одного типа вопросов. Это ожидаемо: различение определяется не текстом вопроса, а распределением компетенций студентов.

**Практический вывод:** LLM можно использовать как «грубый фильтр» для ранжирования multiple-select вопросов по предполагаемой сложности — не для получения точных цифр, а для сравнения вопросов между собой. Для этой задачи формулу произведения вероятностей следует откалибровать: например, применить нормировку или использовать относительные ранги вместо абсолютных значений.

**Рекомендации для дальнейших исследований:**
- Провести калибровку систематической ошибки: добавить небольшой набор вопросов с известными p-значениями в промпт для «заземления» предсказаний
- Добавить в промпт явный контекст «ответ сразу после чтения темы» и измерить эффект на bias
- Увеличить выборку single-select вопросов для надёжных выводов
- Протестировать на суммативных экзаменах, где диапазон сложности шире
